> 📅 2026-11-26 · 2부. 고전 머신러닝 · ⏱ 예상 학습 시간 40~50분

## 1. 한 줄 요약
**차원 축소(Dimensionality Reduction)** 는 특성(칸)이 수십~수천 개인 데이터를 **정보를 최대한 남기면서 적은 개수의 숫자로 줄이는** 기술입니다. **PCA** 는 데이터가 **가장 넓게 퍼진 방향**을 찾아 그 방향으로 그림자를 내리는 "직선 투영" 방법이고, **t-SNE** 와 **UMAP** 은 "가까웠던 점은 줄인 뒤에도 가깝게" 유지하는 데 집중해 **2D 지도로 그려 보기**에 강한 방법입니다. Day 014의 **차원의 저주**를 피하고, 계산을 빠르게 하고, 사람 눈으로 고차원 데이터를 들여다볼 때 씁니다.

```
  64차원 (8×8 손글씨 숫자 이미지)              2차원 지도
  ┌────────────────────────────┐              ·  0 0 0        3 3
  │ 픽셀1 픽셀2 … 픽셀64 │ 정답 │  ── 축소 ──▶   0 0      5 5   3 3 3
  │  0     3   …  12    │  7   │              6 6       5 5    9 9
  │  0     0   …   0    │  1   │              6 6 6   4 4      9 8 8
  └────────────────────────────┘                     4 4   1 1  8 8
  "사람이 볼 수 없는 64개 숫자"                   "같은 숫자끼리 모인 게 보인다"
```

## 2. 핵심 용어
| 용어 | 뜻 | 예시 |
|---|---|---|
| 차원 (Dimension) | 데이터 한 개를 나타내는 숫자(특성)의 개수 | 8×8 이미지 = 64차원 |
| 차원 축소 | 특성 개수를 줄이되 중요한 구조는 남기는 것 | 64 → 2 |
| 특성 선택 vs 특성 추출 | 기존 칸 중 일부만 고르기 vs 기존 칸을 섞어 새 칸 만들기 | PCA = 추출 |
| 분산 (Variance) | 값이 얼마나 넓게 퍼져 있는가 | 퍼짐 = 정보 |
| PCA (주성분 분석) | 분산이 가장 큰 방향(주성분)들로 좌표축을 새로 잡는 선형 방법 | `PCA(n_components=2)` |
| 주성분 (Principal Component) | 데이터가 가장 많이 퍼진 방향. PC1 ⟂ PC2 ⟂ … | PC1 = "전체 크기" 방향 |
| 설명된 분산 비율 | 각 주성분이 전체 퍼짐 중 몇 %를 담는가 | PC1 = 72% |
| 재구성 오차 | 줄였다가 다시 원래 차원으로 되돌렸을 때 생기는 차이 | 압축 손실 |
| 고유벡터 / 고윳값 | 공분산 행렬의 "방향"과 그 방향의 "퍼짐 크기" | PCA의 수학적 정체 |
| t-SNE | 가까운 이웃 관계를 확률로 바꿔 2D에서도 유지하는 비선형 방법 | 시각화 전용 |
| perplexity | t-SNE가 "이웃"으로 볼 대략적인 점 개수 | 5~50, 기본 30 |
| UMAP | 이웃 그래프를 만들어 저차원에 펼치는 비선형 방법. t-SNE보다 빠르고 전체 구조도 더 남김 | `UMAP(n_neighbors=15)` |
| 매니폴드 (Manifold) | 고차원 속에 숨어 있는 휘어진 저차원 면 | 말린 종이(스위스 롤) |

## 3. 개념과 작동 원리

### 3-1. 왜 줄이나
| 이유 | 설명 |
|---|---|
| 차원의 저주 회피 | 특성이 많으면 거리가 의미를 잃음 (Day 014) → k-NN·군집화 성능 저하 |
| 계산·저장 절약 | 1000칸 → 50칸이면 메모리·학습 시간이 크게 줄어듦 |
| 잡음 제거 | 작은 분산 방향은 대개 잡음 → 버리면 오히려 깨끗해짐 |
| 시각화 | 사람은 2D·3D만 볼 수 있음 → 군집이 보이는지 확인 |
| 중복 제거 | 지름과 무게처럼 같이 움직이는 특성은 하나로 합칠 수 있음 |

### 3-2. PCA — "가장 넓게 퍼진 방향으로 그림자 내리기"
```
 무게                                   PC1 축 위로 그림자를 내리면
   │            ● ●  ╱ PC1(가장 넓게 퍼진 방향)
   │         ● ●  ●╱                    ──●──●●──●●●──●●──●──●── PC1
   │       ●  ● ●╱●                     2차원 → 1차원, 퍼짐은 대부분 유지
   │     ● ●  ●╱●
   │   ●  ● ●╱  ╲ PC2 (PC1과 직각, 남은 퍼짐)    PC2 방향 퍼짐은 작다
   │  ● ●  ╱      ╲                       → 버려도 잃는 정보가 적다
   └──────────────────── 지름
```
PCA 4단계:
```
 ① 각 특성에서 평균을 빼서 데이터 중심을 원점으로 옮긴다 (필요하면 표준화도)
 ② 공분산 행렬을 구한다 — "어느 특성끼리 같이 움직이나"
 ③ 공분산 행렬의 고유벡터(방향)와 고윳값(그 방향의 분산)을 구한다
 ④ 고윳값이 큰 순서로 k개 방향을 골라, 데이터를 그 축들에 투영한다
```
- 주성분끼리는 항상 **직각(서로 상관없음)** 입니다.
- 각 주성분은 원래 특성들의 **가중합**입니다. 예: PC1 = 0.7×지름 + 0.7×무게 → "전체 크기"라는 새 특성.
- 몇 개를 남길지: 보통 **누적 설명 분산이 90~95%** 가 되는 지점까지 남깁니다.

### 3-3. PCA의 한계 — 휘어진 구조
PCA는 **직선(평면) 방향으로만** 자릅니다. 데이터가 휘어진 면 위에 놓여 있으면 실패합니다.
```
 스위스 롤(말린 종이) — 실제로는 펼치면 2D 종이 한 장

        ╭──────╮            PCA: 위에서 그림자를 찍음         t-SNE/UMAP: 종이를 펼침
      ╭─╯ ╭──╮ ╰─╮          → 안쪽과 바깥쪽 층이 겹쳐 버림     → 이웃 관계 그대로 펴짐
      │ ╭─╯  ╰╮  │           1 5 2 6 3 7                       1 2 3 4 5 6 7 8
      │ ╰─────╯  │           (멀리 있던 점이 붙음)               (가까운 점끼리 이웃)
      ╰──────────╯
```

### 3-4. t-SNE — 이웃 관계를 확률로 옮겨 적기
```
 ① 고차원에서: 각 점마다 "이 점의 이웃일 확률"을 가우시안(종 모양)으로 계산
              가까우면 확률 높음, 멀면 거의 0
 ② 2D에 점들을 아무렇게나 뿌려 놓고, 2D에서도 같은 식으로 확률 계산
    (2D 쪽은 꼬리가 두꺼운 t-분포 → 먼 점들이 더 멀리 밀려나 군집이 또렷해짐)
 ③ 두 확률 분포가 비슷해지도록(KL 발산 최소화) 2D 점들을 조금씩 이동
```
| 꼭 알아야 할 주의점 | 이유 |
|---|---|
| **군집 사이 거리·군집 크기는 의미 없음** | 이웃 관계만 맞추므로, "A 군집이 B보다 멀다"는 해석 불가 |
| 실행할 때마다 모양이 다름 | 무작위 시작 → `random_state` 고정 필요 |
| 새 데이터를 변환(transform) 못 함 | 학습한 데이터 자체의 지도만 만듦 |
| 느림 | 수만 개 이상이면 오래 걸림 |
| perplexity에 따라 모양이 바뀜 | 작으면 잘게 쪼개지고, 크면 뭉개짐 |

### 3-5. UMAP — 이웃 그래프를 펼치기
```
 ① 각 점에서 n_neighbors개 가까운 이웃을 찾아 "이웃 그래프"(점과 연결선)를 만든다
 ② 저차원에 점을 놓고, 연결된 점은 당기고 연결 안 된 점은 밀어낸다
 ③ 그래프 모양이 최대한 비슷해질 때까지 반복
```
| 비교 | PCA | t-SNE | UMAP |
|---|---|---|---|
| 방식 | 선형 (직선 투영) | 비선형 (이웃 확률) | 비선형 (이웃 그래프) |
| 속도 | 매우 빠름 | 느림 | 빠름 |
| 휘어진 구조 | ❌ | ✅ | ✅ |
| 군집 사이 전체 배치 | ✅ 의미 있음 | ❌ 의미 약함 | △ 어느 정도 유지 |
| 새 데이터 변환 | ✅ `transform` | ❌ | ✅ `transform` |
| 축의 의미 해석 | ✅ (가중합) | ❌ | ❌ |
| 주 용도 | 전처리·압축·잡음 제거 | 시각화 | 시각화 + 전처리 |

> 실무 순서: 특성이 아주 많으면 **PCA로 50차원쯤 먼저 줄이고 → t-SNE/UMAP으로 2D** 로 그리는 경우가 많습니다.

## 4. 구조 — 차원 축소는 파이프라인의 어디에 들어가나
```
 ┌────────┐  스케일링  ┌──────────┐  64→20  ┌──────────┐   ┌──────────┐
 │ 원본 X  │ ───────▶ │ Standard │ ──────▶ │   PCA    │ ─▶ │ 분류/군집 │   ← 전처리 용도
 │ (n×64) │          │ Scaler   │         │ (n×20)   │    │  모델     │
 └────────┘          └──────────┘         └──────────┘   └──────────┘
      │
      └──────────▶ t-SNE / UMAP ──▶ (n×2) ──▶ 산점도로 눈으로 확인          ← 시각화 용도

 PCA가 기억하는 것: 평균 벡터(64개) + 주성분 방향 k개(k × 64)  → 새 데이터도 같은 축으로 변환
 압축과 복원:  X(64) ──투영──▶ Z(k) ──역투영──▶ X̂(64),  재구성 오차 = |X − X̂|
```

## 5. 어디에 쓰이나
| 분야 | 예시 |
|---|---|
| 데이터 탐색 | 고객·센서 데이터를 2D로 그려 군집·이상치가 있는지 먼저 확인 |
| 임베딩 시각화 | 문장·이미지 임베딩(수백~수천 차원)을 UMAP으로 그려 비슷한 것끼리 모였는지 확인 |
| 이미지 압축·얼굴 인식 | PCA로 얼굴을 소수의 "고유얼굴(eigenface)" 조합으로 표현 |
| 잡음 제거 | 작은 주성분을 버리고 복원 → 센서 잡음·이미지 잡음 감소 |
| 전처리 | k-NN, 군집화 전에 차원을 줄여 속도·성능 향상 |
| 생물정보학 | 세포 수만 개 × 유전자 수만 개 데이터를 UMAP으로 그려 세포 종류 구분 |
| 제조·로봇 | 수십 개 센서를 몇 개 주성분으로 요약해 이상 감지 지표로 사용 |

## 6. 코드로 보기 — 숫자 손글씨(64차원)를 2D로

### 6-1. PCA를 직접 계산하기 (부품 지름·무게)
```python
import numpy as np

rng = np.random.default_rng(0)
size = rng.normal(0, 1, 200)                       # 숨은 "크기" 요인
X = np.column_stack([10 + 2.0 * size + rng.normal(0, 0.4, 200),    # 지름(mm)
                     50 + 8.0 * size + rng.normal(0, 2.0, 200)])   # 무게(g)
Xs = (X - X.mean(axis=0)) / X.std(axis=0)          # ① 표준화

cov = np.cov(Xs, rowvar=False)                     # ② 공분산 행렬
vals, vecs = np.linalg.eigh(cov)                   # ③ 고윳값·고유벡터
order = vals.argsort()[::-1]
vals, vecs = vals[order], vecs[:, order]
ratio = vals / vals.sum()

print("공분산 행렬:\n", cov.round(3))
for i in range(2):
    print(f"PC{i+1}: 방향 = [{vecs[0, i]:+.3f}, {vecs[1, i]:+.3f}]  설명 분산 = {ratio[i]:.1%}  "
          + "█" * round(ratio[i] * 40))

Z = Xs @ vecs[:, :1]                               # ④ PC1 하나로 투영 (2D → 1D)
X_back = Z @ vecs[:, :1].T                          # 다시 2D로 복원
err = ((Xs - X_back) ** 2).sum(axis=1).mean()
print(f"\n2D → 1D 압축 후 복원 오차(평균 제곱) = {err:.4f}  (전체 분산 2.0 중)")
print("처음 3개 부품의 PC1 점수:", Z[:3, 0].round(2))
```
- 지름과 무게는 상관이 0.955로 거의 같이 움직입니다. 그래서 **PC1 하나가 퍼짐의 97.5%** 를 담습니다.
- PC1 방향 [-0.707, -0.707]은 "지름과 무게를 똑같은 비율로 섞은 축", 즉 **"부품 크기"** 라는 새 특성입니다. 부호(−)는 방향만 뒤집힌 것이라 의미 차이가 없습니다.
- 2D를 1D로 줄였다가 복원해도 오차는 0.05로, 전체 분산 2.0의 2.5% 수준입니다. 이 값이 바로 버린 PC2의 몫입니다.
실행 결과
```
공분산 행렬:
 [[1.005 0.955]
 [0.955 1.005]]
PC1: 방향 = [-0.707, -0.707]  설명 분산 = 97.5%  ███████████████████████████████████████
PC2: 방향 = [+0.707, -0.707]  설명 분산 = 2.5%  █

2D → 1D 압축 후 복원 오차(평균 제곱) = 0.0498  (전체 분산 2.0 중)
처음 3개 부품의 PC1 점수: [-0.01  0.19 -0.42]
```

### 6-2. 몇 개까지 줄여도 될까 — 누적 설명 분산
```python
import numpy as np
from sklearn.datasets import load_digits
from sklearn.decomposition import PCA
from sklearn.model_selection import cross_val_score
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_digits(return_X_y=True)                # 1797장, 8×8 = 64차원
print("데이터 크기:", X.shape)

pca = PCA().fit(StandardScaler().fit_transform(X))
cum = np.cumsum(pca.explained_variance_ratio_)
print("\n주성분 수  누적 설명 분산")
for k in [1, 2, 5, 10, 20, 30, 40, 64]:
    print(f"   {k:>3}       {cum[k-1]:6.1%}  " + "█" * round(cum[k-1] * 30))
print("90%를 넘는 최소 주성분 수:", int(np.argmax(cum >= 0.90)) + 1)

print("\nk-NN(k=5) 5겹 교차검증 정확도")
for k in [2, 5, 10, 20, 64]:
    model = make_pipeline(StandardScaler(), PCA(n_components=k), KNeighborsClassifier(5))
    acc = cross_val_score(model, X, y, cv=5).mean()
    print(f"   {k:>3}차원  {acc:6.1%}  " + "█" * round(acc * 30))
```

### 6-3. PCA vs t-SNE vs UMAP — 2D 지도 비교
```python
import time, warnings
import numpy as np
from sklearn.datasets import load_digits
from sklearn.decomposition import PCA
from sklearn.manifold import TSNE
from sklearn.model_selection import cross_val_score
from sklearn.neighbors import KNeighborsClassifier
import umap
warnings.filterwarnings("ignore")

X, y = load_digits(return_X_y=True)
methods = {
    "PCA":   lambda: PCA(n_components=2, random_state=0),
    "t-SNE": lambda: TSNE(n_components=2, perplexity=30, random_state=0),
    "UMAP":  lambda: umap.UMAP(n_components=2, n_neighbors=15, random_state=0),
}
maps = {}
print("방법     시간    2D에서 k-NN 정확도 (같은 숫자가 잘 모였나)")
for name, make in methods.items():
    t0 = time.time()
    Z = make().fit_transform(X)
    sec = time.time() - t0
    acc = cross_val_score(KNeighborsClassifier(5), Z, y, cv=5).mean()
    maps[name] = Z
    print(f"{name:<6} {sec:5.1f}초   {acc:6.1%}  " + "█" * round(acc * 30))

def draw(Z, title, w=46, h=14):
    grid = [[" "] * w for _ in range(h)]
    lo, hi = Z.min(axis=0), Z.max(axis=0)
    for (a, b), label in zip(Z[::3], y[::3]):          # 3장에 1장만 찍어 덜 빽빽하게
        c = int((a - lo[0]) / (hi[0] - lo[0]) * (w - 1))
        r = int((hi[1] - b) / (hi[1] - lo[1]) * (h - 1))
        grid[r][c] = str(label)
    print(f"\n[{title}]  (글자 = 실제 숫자)")
    for row in grid:
        print("  " + "".join(row))

draw(maps["PCA"], "PCA 2D")
draw(maps["t-SNE"], "t-SNE 2D")
```

7. 새로 들어오는 데이터를 같은 2D 지도 위에 계속 찍어야 한다면 t-SNE와 UMAP 중 무엇이 적합한가요?

<summary>정답 보기</summary>

1. 데이터가 가장 넓게 퍼진(분산이 가장 큰) 방향
2. 서로 직각(직교)이고, 서로 상관이 없다
3. 원래 데이터 퍼짐(정보)의 90%를 담을 만큼만 주성분을 남기고 나머지는 버린다는 뜻
4. PCA는 분산이 큰 방향을 찾는데, 단위가 큰 특성(예: 무게 g)이 분산을 독차지해 방향을 왜곡하기 때문
5. PCA는 직선(평면) 방향으로만 투영하므로, 휘어진 면에서 멀리 떨어진 층이 겹쳐 버린다
6. t-SNE는 가까운 이웃 관계만 맞추도록 최적화되어, 군집 사이 거리와 군집 크기는 의미가 보장되지 않기 때문
7. UMAP. `transform`으로 새 데이터를 기존 지도에 넣을 수 있다 (t-SNE는 다시 전부 계산해야 함)
