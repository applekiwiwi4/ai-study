# Day 014 — k-NN과 거리 기반 학습

> 📅 2026-11-24 · 2부. 고전 머신러닝 · ⏱ 예상 학습 시간 40~50분

## 1. 한 줄 요약
**k-NN(k-Nearest Neighbors, k-최근접 이웃)** 은 "새 데이터와 **가장 가까운 이웃 k개**를 찾아서, 그 이웃들이 많이 속한 쪽으로 답한다"는 아주 단순한 모델입니다. "끼리끼리 모인다"는 원리입니다. 학습 단계에서는 데이터를 **외워 두기만** 하고, 실제 계산은 예측할 때 합니다(게으른 학습). 결과는 **거리를 어떻게 재느냐**와 **k를 몇으로 하느냐**에 크게 좌우됩니다. 얼굴 인식의 "등록된 얼굴 중 가장 비슷한 사람 찾기", 추천 시스템, LLM의 벡터 검색(RAG)이 모두 이 "가장 가까운 것 찾기" 원리 위에 서 있습니다.

```
 무게(g)                                     새 부품 ★ 는 볼트일까 너트일까?
   │   ▲  ▲                                  k = 3 → 가장 가까운 3개를 본다
   │ ▲   ▲    ▲         ▲ 볼트                ● ● ▲  → 너트 2 : 볼트 1 → "너트"
   │    ▲  ╭───────╮     ● 너트
   │      │ ●  ★ ▲│                          k = 7 → 가장 가까운 7개를 본다
   │   ●  │   ●   │ ●                         ● ● ● ● ▲ ▲ ▲ → 너트 4 : 볼트 3 → "너트"
   │  ●   ╰───────╯   ●
   │    ●    ●   ●                           ※ k에 따라 답이 바뀔 수 있다
   └──────────────────────── 지름(mm)
```

## 2. 핵심 용어
| 용어 | 뜻 | 예시 |
|---|---|---|
| 최근접 이웃 (Nearest Neighbor) | 새 점과 거리가 가장 가까운 훈련 데이터 | 가장 비슷한 부품 |
| k | 예측에 참고할 이웃의 개수 | k = 5 |
| 다수결 투표 (Majority Vote) | 이웃 중 가장 많은 클래스를 답으로 고름 (분류) | 너트 3, 볼트 2 → 너트 |
| 평균 (Mean) | 이웃들의 값을 평균 내서 답으로 씀 (회귀) | 이웃 무게 평균 |
| 거리 가중 (Distance Weighting) | 가까운 이웃의 표에 더 큰 가중치 | `weights="distance"` |
| 게으른 학습 (Lazy Learning) | 학습 때는 저장만 하고, 예측 때 계산하는 방식 | k-NN |
| 유클리드 거리 (Euclidean, L2) | 두 점 사이의 직선 거리 `√Σ(aᵢ-bᵢ)²` | 자로 잰 거리 |
| 맨해튼 거리 (Manhattan, L1) | 축을 따라 움직인 거리 `Σ|aᵢ-bᵢ|` | 바둑판 도로 거리 |
| 코사인 거리 (Cosine) | `1 - 코사인 유사도`. 방향이 얼마나 다른가 (Day 007) | 문서·임베딩 비교 |
| 특성 스케일링 (Scaling) | 특성 범위를 맞추는 것. 거리 기반 모델에서 **필수** | `StandardScaler` |
| 차원의 저주 (Curse of Dimensionality) | 특성 수가 많아지면 모든 점이 비슷하게 멀어져 "가까움"이 의미를 잃는 현상 | 특성 1000개 |
| KD-트리 / 근사 최근접 탐색 (ANN) | 모든 점과 거리를 재지 않고 빨리 이웃을 찾는 자료구조·알고리즘 | FAISS, HNSW |

## 3. 개념과 작동 원리

### 3-1. 알고리즘 — 정말 이게 전부입니다
```
 [학습]  훈련 데이터 (X, y)를 그대로 저장한다. 끝.

 [예측]  새 점 x가 들어오면
   ① x와 모든 훈련 점 사이의 거리를 계산한다
   ② 거리가 가장 짧은 k개를 고른다
   ③ 분류: 그 k개 중 가장 많은 클래스 / 회귀: 그 k개의 평균값
```
> 다른 모델은 학습할 때 가중치(w, b)나 트리를 만들어 두지만, k-NN에는 **학습해서 얻는 숫자가 없습니다**. 데이터 자체가 모델입니다.

### 3-2. 거리 재는 방법
두 부품 A = (지름 8, 무게 10), B = (지름 11, 무게 14)의 거리를 재 봅니다.
```
 무게
  14 ┤             ● B
     │            ╱│
     │  유클리드 ╱  │ 4 (무게 차)        유클리드 = √(3² + 4²) = √25 = 5
     │   = 5   ╱   │                    맨해튼   = 3 + 4      = 7
  10 ┤  A ●───────┘
     │      3 (지름 차)
     └────┬───────┬──── 지름
          8      11
```
| 거리 | 식 | 특징 | 주로 쓰는 곳 |
|---|---|---|---|
| 유클리드 (L2) | `√Σ(aᵢ-bᵢ)²` | 직선 거리, 큰 차이를 더 크게 반영 | 기본값, 좌표·센서값 |
| 맨해튼 (L1) | `Σ|aᵢ-bᵢ|` | 이상치에 덜 민감 | 격자 이동, 특성이 많을 때 |
| 코사인 | `1 - (a·b)/(‖a‖‖b‖)` | 크기 무시, **방향**만 비교 | 문서, 얼굴·문장 임베딩 |
| 해밍 | 다른 자리의 개수 | 0/1, 문자열 | 바코드, 유전자 서열 |

### 3-3. k를 어떻게 정할까
```
 k = 1 (가장 가까운 1개만)            k = 15 (적당히 여러 개)              k = 전체 (모든 데이터)
  경계가 들쭉날쭉, 노이즈에 민감        경계가 부드러움                      항상 다수 클래스만 답함
  ○○●○○●○○                           ○○○○│●●●                            ○○○○○○○○
  ○●○○○●●●   ← 섬이 생김               ○○○○│●●●                            ○○○○○○○○
  훈련 정확도 100% (자기 자신이 이웃)   훈련·검증이 비슷하게 좋음            경계 자체가 없음
  → 과적합                                                               → 과소적합
```
| k | 경계 | 위험 |
|---|---|---|
| 작음 (1~3) | 복잡, 들쭉날쭉 | 과적합, 노이즈 한 점에 휘둘림 |
| 적당함 | 부드러움 | — |
| 큼 | 지나치게 단순 | 과소적합, 소수 클래스를 무시 |

- 이진 분류에서는 동점을 피하려고 **홀수 k**를 많이 씁니다.
- 보통 **검증 데이터로 여러 k를 시험해서** 고릅니다 (6-2 코드). 경험적으로 `√(훈련 데이터 수)` 근처에서 시작하기도 합니다.

### 3-4. 거리 가중 투표
k = 5인데 이웃이 이렇게 있다면?
```
 거리:   0.5(너트)   0.6(너트)   3.0(볼트)   3.1(볼트)   3.2(볼트)
 단순 다수결:  너트 2 vs 볼트 3 → "볼트"           ← 멀리 있는 볼트들이 이김
 거리 가중(1/거리): 너트 2.0+1.67=3.67 vs 볼트 0.33+0.32+0.31=0.96 → "너트"  ← 바로 옆 이웃을 존중
```

### 3-5. 스케일링이 왜 필수인가
지름은 5~15mm, 무게는 1000~5000g(가상)처럼 **범위가 다르면** 거리는 거의 무게 차이로만 결정됩니다.
```
 A = (지름 6,  무게 2000)    B = (지름 14, 무게 2010)    C = (지름 6, 무게 2100)
 거리(A, B) = √(8² + 10²)  ≈ 12.8   ← 지름이 완전히 다른데 "가깝다"
 거리(A, C) = √(0² + 100²) = 100    ← 지름이 같은데 "멀다"
 → 무게 단위가 커서 지름 차이가 묻혀 버림. 표준화(Day 002)로 범위를 맞춰야 함
```

### 3-6. 차원의 저주
특성(차원)이 많아질수록 이상한 일이 생깁니다.
```
 차원 수      가장 가까운 점 거리 / 가장 먼 점 거리
   2           0.02      → 가까운 점과 먼 점이 확실히 구분됨
   10          0.31
   100         0.71
   1000        0.88      → 모든 점이 거의 비슷한 거리 → "가장 가까운 이웃"이 의미를 잃어 감
 (무작위 점 500개로 측정한 값, 6-3 코드 실행 결과)
```
- 그래서 원본 픽셀(수십만 차원)로 k-NN을 하면 잘 안 됩니다.
- 해결: **차원 축소**(PCA, Day 016) 또는 딥러닝으로 **의미 있는 저차원 임베딩**(얼굴 512차원 등)을 먼저 만든 뒤 k-NN을 합니다. 이것이 현대 얼굴 인식·검색의 기본 구조입니다.

### 3-7. 빠르게 찾기 — KD-트리와 근사 최근접 탐색
| 방법 | 방식 | 언제 |
|---|---|---|
| 전수 탐색 (brute force) | 모든 점과 거리 계산 | 데이터 수천 개 이하 |
| KD-트리 / Ball-트리 | 공간을 상자로 나눠 먼 상자는 건너뜀 | 저차원(~20) 데이터 |
| 근사 탐색 (ANN: HNSW, IVF) | 100% 정확하진 않지만 수백 배 빠르게 | 수백만~수십억 개 벡터 (벡터 DB, Day 048) |

## 4. 구조 — 학습과 예측 비용
```
                 학습 시간          예측 시간 (데이터 n개, 특성 d개)        저장 공간
 k-NN           거의 0 (저장만)     느림: 매번 n개와 거리 계산 O(n·d)        데이터 전체
 로지스틱 회귀   반복 학습 필요       빠름: w·x 한 번 O(d)                     w, b만
 결정 트리       트리 생성 필요       빠름: 질문 깊이만큼                      트리 구조

 ┌───────────┐   저장    ┌──────────────────┐
 │ 훈련 데이터 │ ───────▶ │  메모리 (데이터 = 모델) │
 └───────────┘          └─────────┬────────┘
                                  │ ① 거리 계산 (n번)
   새 데이터 x ───────────────────▶│ ② 가까운 k개 선택
                                  │ ③ 투표 / 평균
                                  ▼
                               예측 결과
```
> 장점: 새 데이터를 **다시 학습 없이 바로 추가**할 수 있습니다. 얼굴 인식 출입 시스템에서 새 직원 얼굴을 등록만 하면 바로 인식되는 이유입니다.

## 6. 코드로 보기 — 부품 분류 (볼트 vs 너트)

### 6-1. k-NN을 직접 구현하고 이웃 확인하기
```python
import numpy as np
from collections import Counter

# 훈련 데이터: [지름(mm), 무게(g)]
X = np.array([[6, 4], [7, 5], [6, 6], [8, 5], [7, 7],          # 볼트
              [10, 9], [11, 10], [12, 9], [11, 12], [10, 11]])  # 너트
y = np.array(["볼트"] * 5 + ["너트"] * 5)

def knn_predict(x_new, X, y, k):
    dists = np.sqrt(((X - x_new) ** 2).sum(axis=1))     # ① 유클리드 거리
    idx = np.argsort(dists)[:k]                          # ② 가까운 k개
    votes = Counter(y[idx])                              # ③ 다수결
    return votes.most_common(1)[0][0], idx, dists

x_new = np.array([9, 8])
for k in [1, 3, 5]:
    label, idx, dists = knn_predict(x_new, X, y, k)
    neigh = ", ".join(f"{y[i]}({dists[i]:.2f})" for i in idx)
    print(f"k={k}: 이웃 [{neigh}] → 예측: {label}")

print("\n거리 비교: 유클리드 vs 맨해튼 (A=(8,10), B=(11,14))")
A, B = np.array([8, 10]), np.array([11, 14])
print(f"  유클리드 = {np.sqrt(((A - B) ** 2).sum()):.1f},  맨해튼 = {np.abs(A - B).sum()}")
```
실행 결과
```
k=1: 이웃 [너트(1.41)] → 예측: 너트
k=3: 이웃 [너트(1.41), 볼트(2.24), 너트(2.83)] → 예측: 너트
k=5: 이웃 [너트(1.41), 볼트(2.24), 너트(2.83), 볼트(3.16), 너트(3.16)] → 예측: 너트

거리 비교: 유클리드 vs 맨해튼 (A=(8,10), B=(11,14))
  유클리드 = 5.0,  맨해튼 = 7
```

### 6-2. k에 따른 경계 모양과 과적합
```python
import numpy as np
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier

X, y = make_moons(n_samples=300, noise=0.35, random_state=2)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0)

print("  k     훈련    테스트")
for k in [1, 3, 7, 15, 31, 101, 209]:
    m = KNeighborsClassifier(n_neighbors=k).fit(X_tr, y_tr)
    tr, te = m.score(X_tr, y_tr), m.score(X_te, y_te)
    print(f" {k:>3}   {tr:5.0%}   {te:5.0%}  {'█' * round(te * 30)}")

for k in [1, 15]:
    m = KNeighborsClassifier(n_neighbors=k).fit(X_tr, y_tr)
    print(f"\n[k={k}] 판정 영역 (●=클래스1)")
    for r in range(9):
        row = ""
        for c in range(36):
            x1, x2 = -1.5 + c / 35 * 4, 1.6 - r / 8 * 2.4
            row += "●" if m.predict([[x1, x2]])[0] else "·"
        print("   " + row)
```

- k가 너무 크면(훈련 데이터 전체인 209) 무조건 다수 클래스만 답해 성능이 떨어집니다. **과소적합**입니다.
- 그 사이 어딘가에서 테스트 정확도가 가장 높습니다.

### 6-3. 스케일링의 효과와 차원의 저주
```python
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

# (1) 단위가 다른 특성: 지름(mm, 결정적) + 무게(g, 범위만 크고 거의 무관)
rng = np.random.default_rng(0)
n = 400
diameter = np.concatenate([rng.normal(7, 1, n // 2), rng.normal(10, 1, n // 2)])
weight = rng.normal(3000, 800, n)                    # 두 클래스에서 분포가 같음
X = np.column_stack([diameter, weight])
y = np.array([0] * (n // 2) + [1] * (n // 2))
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=0)

raw = KNeighborsClassifier(n_neighbors=7).fit(X_tr, y_tr)
scaled = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=7)).fit(X_tr, y_tr)
print("(1) 지름(mm) + 무게(g) 로 분류한 테스트 정확도")
print(f"   스케일링 없음 : {raw.score(X_te, y_te):.0%}  {'█' * round(raw.score(X_te, y_te) * 30)}")
print(f"   StandardScaler: {scaled.score(X_te, y_te):.0%}  {'█' * round(scaled.score(X_te, y_te) * 30)}")

# (2) 차원의 저주: 차원이 커질수록 "가장 가까운 점 / 가장 먼 점" 거리 비율이 1에 가까워짐
print("\n(2) 차원 수   가장 가까운 거리 / 가장 먼 거리")
for d in [2, 10, 100, 1000]:
    pts = rng.random((500, d))
    q = rng.random(d)
    dist = np.sqrt(((pts - q) ** 2).sum(axis=1))
    ratio = dist.min() / dist.max()
    print(f"   {d:>5}       {ratio:.2f}  {'█' * round(ratio * 30)}")
```
실행 결과
```
(1) 지름(mm) + 무게(g) 로 분류한 테스트 정확도
   스케일링 없음 : 42%  █████████████
   StandardScaler: 96%  █████████████████████████████

(2) 차원 수   가장 가까운 거리 / 가장 먼 거리
       2       0.02  █
      10       0.31  █████████
     100       0.71  █████████████████████
    1000       0.88  ███████████████████████████
```
- 무게는 범위만 크고 클래스와 관계가 없는데, 스케일링하지 않으면 거리가 무게에 지배당해 성능이 크게 떨어집니다. **k-NN도 SVM(Day 013)처럼 스케일링이 필수**입니다.
- 차원이 1000이 되면 가장 가까운 점과 가장 먼 점의 거리가 거의 같아져, "가장 가까운 이웃"을 찾는 의미가 약해집니다. 그래서 고차원 원본 데이터는 먼저 의미 있는 저차원 특징(임베딩)으로 바꾼 뒤 k-NN을 적용합니다.
